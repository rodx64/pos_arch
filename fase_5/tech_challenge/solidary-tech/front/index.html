Arquitetura de microsserviços

Três domínios, uma missão

Cada serviço tem responsabilidade única, persistência adequada ao domínio e instrumentação completa via OpenTelemetry.

💚
donation-service
Gerencia o fluxo de transações de doação. Persiste no PostgreSQL (RDS) e publica eventos no SQS. Serviço crítico de SLO com KEDA escalando por tráfego HTTP via Prometheus.
GoPostgreSQLSQSKEDA
🏢
ngo-service
Cadastro e gestão das ONGs parceiras. Pool de conexão psycopg2, Gunicorn reduzido para 2 workers — escala horizontal via HPA, não vertical por processo.
PythonFlaskPostgreSQLHPA
🙋
volunteer-service
Registro e busca de voluntários por ONG. Dados no DynamoDB com PITR habilitado (RPO ~segundos). Credenciais AWS via IMDS — compatível com LabRole do AWS Academy.
PythonFlaskDynamoDBHPA
